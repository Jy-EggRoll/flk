# flk serve 的浏览器端 E2E

用**真实 Chromium** 跑一遍 `flk serve` 的 WebUI：逐条断言自动截图、整场录屏、收尾生成可以直接给人看的回看页 `report.html`。

它与 `task verify`（Go 单测那套门禁）是两件事：单元测试证明不了「拖选文字会不会被当成整行拖拽」「保存时自己的 SSE 会不会被当成外部修改」这类接缝。本次改造就是靠这套脚本抓出 3 个真实缺陷：

1. 输入框内拖选文字被误判成整行拖拽，导致行序被改坏
2. 保存时自己触发的 SSE 被误判成「外部修改」，弹出冲突提示
3. 索引越界会静默改坏配置（不报错、界面看不出异常）

所以它**按需跑**，刻意不挂进 `default`：改一次代码就跑一遍全套断言（编写本索引时 31 条，见下方索引）的浏览器验收，代价与收益不成比例

## 怎么跑

```bash
task verify:browser                 # 推荐：自动构建到临时路径 → 起服务 → 跑断言 → 生成回看页
task verify:browser ONLY=B1,B2,B3   # 只跑指定编号，调断言时省时间
task verify:browser LABEL=before    # 给现场起个名字，便于前后对比
```

手动跑（换二进制、换现场目录做对比）：

```bash
cd tools/e2e && pnpm install        # 只需一次
node verify.mjs --binary=build/flk --root=.task/e2e --label=local
```

`--binary` 与 `--root` 都是必填，缺了会打印中文用法并以退出码 2 结束（与「断言失败」的 1 区分开）。脚本内不含任何仓库外的绝对路径

## 产物

全部落在 `--root` 下（Taskfile 默认 `.task/e2e`，`.gitignore` 第 2 行已忽略 `.task/`，不会出现在 `git status` 里）：

```
.task/e2e/runs/<时间戳>/report.html    回看页：录屏在最上，之后每条断言一张卡片
.task/e2e/runs/<时间戳>/shots/*.png    每条断言一张截图，失败那张就是证据
.task/e2e/runs/<时间戳>/video/*.mp4    整场录屏（默认放慢 3 倍，便于复审）
.task/e2e/runs/<时间戳>/run.log        控制台全文
.task/e2e/runs/<时间戳>/serve-*.log    被测进程的 stdout/stderr
.task/e2e/work/<label>-<时间戳>/       本次的临时 store 与夹具文件，刻意保留便于事后复现
```

现场刻意不放 `build/`：`task clean` 是 `rm -rf build/`，放那儿会被顺手删掉。`.task/` 是 Task 自己的元数据目录，`clean` 不碰它，要清现场就自己删 `.task/e2e`

## 断言索引：每条断言到底在守护什么

用途：日后判断「某条断言是否还代表契约」。断言的权威定义是 `tools/e2e/verify.mjs` 里的 `await check(...)` 与它的 `expect()` 期望值，这份索引只是索引，**以脚本为准**

规格文档（设计期的契约，未入库）与脚本冲突时以脚本为准——脚本是实测中反复收紧过的判定，例如「拖选劫持」与「保存窗口」两条本来就是先有实测缺陷、后补进契约的（spec §4.7 / §4.8），脚本里的 X7.x / X12.x 比规格描述更严

### B 系列：契约主干（对应规格第 4 节 B1–B13）

| 编号 | 验什么 | 判定标准（脚本实际断言） | 守护的用户可见行为 |
| --- | --- | --- | --- |
| B1 | 一体化后表格是「常驻可编辑」结构 | 每个字段格都是 `input.cell-input`（共 行数×字段数 个）、不存在 `.cell-text`、页面上没有 `#editBtn` / `#cancelBtn` | 打开页面直接就能改配置，不用先切「编辑模式」 |
| B2 | 改一格后的即时反馈 | `#saveActions` 可见、`#dirtyCount` 为「未保存改动 1 处」、被改的 input 带 `.dirty`、该行徽标 `health-pending` 且文案「待重检」、两个按钮文案是「保存」「撤销改动」 | 用户随时知道「改了什么、存没存」，过期状态不再冒充真实状态 |
| B3 | 撤销改动 | 值回到原值、`#saveActions` 隐藏、磁盘文件逐字节未变、`GET /api/config` 里也不含改动值 | 撤销是安全的，不会偷偷写盘 |
| B4 | 保存真的落盘 | `#saveActions` 隐藏、成功提示出现、磁盘文件里出现新值、`GET /api/config` 也返回新值 | 点保存后配置确实改到了文件里 |
| B5 | 自己保存触发的 SSE 不得弹冲突条（含一闪而过） | 先确认 `#conflictBar` 元素存在（否则「没弹出」只是空真）；保存后用 MutationObserver 监听它 `class`/`style` 的每一次变化，并叠加 25ms 轮询兜底（只靠轮询会因相位误差漏掉 3–5ms 的闪烁，脚本注释记了实测 4 次漏 1 次），要求可见记录为 0，且保存结束后仍隐藏 | 保存过程不冒出一条莫名的「配置文件已在页面上被修改」 |
| B6 | 页面无未保存改动时，外部改文件 | 自动重载并显示外部新值、`#conflictBar` 始终隐藏（同样先确认元素存在） | 别的窗口/进程改了配置，本页面自动跟上 |
| B7 | 有未保存改动时，外部改文件 | `#conflictBar` 出现、`#conflictText` 与两个按钮都是中文契约文案、我的改动仍在输入框、`#saveActions` 仍可见 | 正在编辑的内容不被静默覆盖，且提示能直接决策 |
| B8 | 冲突时选「重新加载（丢弃我的改动）」 | 提示条隐藏、显示外部新值、我的改动被丢弃、`#saveActions` 隐藏 | 想要外部版本时一键切过去 |
| B9 | 冲突时选「保留我的改动」 | 提示条隐藏、输入框里仍是我的值、`#saveActions` 仍可见、脏计数仍为 1 | 想要自己版本时不被外部改动冲掉 |
| B10 | 新增一条 | 行数 +1、脏计数为 1、新行徽标为「待重检」 | 能加条目，且知道新条目还没保存过 |
| B11 | 删除一条 | 行数 -1、脏计数为 1；只删除未保存时 `GET /api/config` 与磁盘都与 pristine 完全一致 | 删除也算一处改动，且不会在保存前写盘 |
| B12 | 常驻结构「什么都不用先做」就可用 | 刚加载时表头 `th.cb-col` + `#cbAll`、`th.drag-handle` + 每行一个 `.drag-handle`、每行一个 `.btn-dell` 都在；全选后勾选数正确且 `#migrateBtn` 可见 | 勾选、拖拽、删除随时可用，不再藏在编辑态里 |
| B13 | 保存成功后计数从 1 重新开始 | 改 `real` 一格计数为 1 → 保存（服务端会重排序，按刚保存的值重新定位目标行）→ 再改同一行的 `fake` 字段 → 计数仍为 1，完整文案「未保存改动 1 处」 | 「未保存改动 N 处」永远只表示当前这一次的改动量 |

### X 系列：针对具体缺陷与风险的加验

| 编号 | 验什么 | 判定标准（脚本实际断言） | 守护什么 |
| --- | --- | --- | --- |
| X1 | 中文模式下有没有英文残留 | 页面可见文本不含 `ENGLISH_RESIDUE` 清单里的英文源串 | 界面语言不自相矛盾（规格第 5 节硬约束） |
| X2 | 页头结构的前置条件 | `#recheckBtn` 常驻且文案「重新检测」；`#conflictBar` 元素存在且默认隐藏 | B5/B6 的「没弹出/保持隐藏」有真实对象，不是空真 |
| X3 | 真实 HTML5 DnD 拖拽还能不能改行序 | 从 `.drag-handle` 真实拖拽后行顺序发生变化（脚本自述**可能 flaky**） | 拖拽功能本身没被改坏；也正因为它 flaky，不能当门禁 |
| X4 | `GET /api/meta` 的 rev | 返回非空字符串 `rev`（规格 §3.2） | 前端有「本页已知版本」的基准 |
| X5 | `POST /api/config` 的响应 | 返回 `{"success":true,"rev":"<非空>"}`（规格 §3.3） | 保存后能把 knownRev 更新成服务端真实版本 |
| X6 | SSE `updated` 的 data | 12s 内收到 data 行、是合法 JSON、含非空 `rev`（规格 §3.4） | 前端能区分「自己保存」与「外部修改」——B5/B6/B7 判定的地基 |
| X7.1–X7.3 | 输入框内拖选文字不得被整行拖拽劫持 | 7.1 同一行内水平拖选：行序不变**且**真的选中了文字（selectionStart/End 非 0）；7.2 跨行拖选（input→input）：行序不变；7.3 从已有选区拖走文本（最易触发原生拖拽）：行序不变 | 想复制/移动一段路径文本时，不会把整行顺序改坏（规格 §4.7） |
| X8.1–X8.2 | `renderTable()` 重建 DOM 后焦点与选区是否保留 | 8.1 由 SSE 自动重载触发重建；8.2 由可用性检测完成触发重建；两次都断言同一 input 仍是 `document.activeElement`、选区与之前一致、值不变 | 正在输入时界面自动刷新，光标与选区不跳（规格 §4.3） |
| X9 | 保存窗口被拉长到肉眼可见后，自己的 SSE 仍不弹条 | 把回给页面的 POST 响应人为延后 800ms，按 25ms 采样，`#conflictBar` 可见次数为 0 | 网络慢时也不会闪出冲突提示（B5 在快速路径下漏掉的区间）（规格 §4.8） |
| X10 | 只记录、不断言：SSE / fetch / 提示条 class 的时间线 | 无行为断言，只把页内 `performance.now` 时间线写进报告 | 定位 B5 那一下闪烁的触发时序；**功能坏了它也不会失败**，别把它当成覆盖 |
| X11.1–X11.2 | 没经过 `dragstart` 的 drop（模拟从页面外拖入）不得重排行序 | 2 行与 3 行两种布局下 drop 后行序不变，且不产生未保存改动 | 从桌面误拖一个文件到表格上，不会把顺序搞乱 |
| X12.1–X12.3 | 保存进行中的编辑不能被吞掉 | 12.1 人为延后响应、窗口内继续输入：第一次请求体只含窗口前的改动、不含窗口内输入，磁盘同理；12.2 第一次保存成功后窗口内编辑仍算未保存（脏计数 > 0、保存按钮仍可见）；12.3 第二次保存把窗口内改动真正落盘，落盘后 `#saveActions` 才隐藏、计数归零 | 点保存那一瞬间继续打字，输入不会被静默丢弃，也不会出现「按钮消失但其实没存上」的假保存（规格 §4.8） |

**B 与 X 的分工**：B1–B13 是契约主干，覆盖三个已定决策（单元格常态可编辑、显式保存、冲突提示条）的正面行为；X 是加验，各有明确来由——接口层 X4–X6（B5–B7 建立在此之上）、实测缺陷回归 X7/X9/X11/X12、渲染接缝 X8、硬约束与前置条件 X1/X2、参照 X3、诊断 X10。B 失败意味着契约被破坏，X 失败意味着某条具体风险回归

**清点与同步**：本索引对应 31 条断言（2026-09-30 编写；脚本还在被追加断言，条数会变，以 `grep` 结果为准）。断言增删后请同步本索引，清点用：

```bash
grep -n "await check(" tools/e2e/verify.mjs
```

## lib/ 是 vendor 副本

`lib/*.mjs` 是从 **browser-verify 技能**（`~/.dsh/skills/browser-verify/lib/`）原样复制的，共 5 个文件：`browser` `artifacts` `report` `video` `toolchain`。它负责三件 Playwright 自己不管的事——定位本机 Chromium、清洗代理变量、把录屏转成兼容性最好的 mp4 并生成回看页

**为什么复制而不是引用**：直接 import 技能目录就得写死一个绝对路径，而技能装在哪台机器、哪个人身上都是可变的；复制进来后脚本跟着仓库走，换机器、换目录、换人都能跑。代价是**会与上游漂移**，所以改这里之前先看上游是不是已经修过

同步方法（上游有更新时整目录覆盖，不要在副本上单独改）：

```bash
cp ~/.dsh/skills/browser-verify/lib/*.mjs tools/e2e/lib/
diff -r ~/.dsh/skills/browser-verify/lib tools/e2e/lib   # 无输出即与上游一致
```
